# To be done

Planned work that is not part of the current release.

## Plant page

A page for every shop item, opened from its card in the shop and on the home page, modelled on the
structure of a plant care guide page (not its content):

- Breadcrumbs: Home, Shop, the plant.
- A hero with the name, the species, a large picture and the order button (a visitor sees "Sign in to order").
- A strip of key facts: difficulty, light, temperature, humidity, growth, soil.
- Short blocks for what matters most: the biggest mistake, what nobody tells you, real home conditions.
- A quick answer and key takeaways, then links to the AI chat and to the journal.

Needs from the backend:

- A `slug` on every item, used for the address (`/shop/<slug>`) and for the picture in the media bucket.
- A detail endpoint, `GET /v1/items/{slug}`, open without a token like the list, that returns the care
  data from the dataset. The list endpoint stays light.

Until that data exists the page would only repeat what the card already shows, so it waits for the dataset.

## Product pictures

Pictures of the items come from the separate media bucket, addressed by `slug`, with the bundled placeholders
shown when a picture is missing. The attribution table is generated by the backend; `docs/credits.md` is built
from it.

## Hardening and measurement

- A strict Content Security Policy for the built application, because the session is kept in `sessionStorage`.
- Lighthouse results for desktop and mobile and a bundle analysis.
