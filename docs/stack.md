# Stack justification

The framework is **React with TypeScript** (the author's decision). Every other choice below was made for a small
single-page application that talks to one gateway, with a strong accessibility and design goal, and a short
delivery time. For each choice the table gives the alternative that was considered and why it was not taken.

| Concern                    | Chosen                                                | Why                                                                                                                                                                                               | Alternative and why not                                                                                                                                                            |
| -------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Framework                  | React 19, TypeScript in strict mode                   | Component model fits the feature modules; the largest ecosystem; strict types catch contract changes at compile time                                                                              | Angular: more structure than a project of this size needs. Vue: no reason to differ from React's tooling for testing and types                                                     |
| Bundler                    | Vite 8                                                | Fast dev server, native ES modules, lazy routes become separate chunks with no configuration, a built-in proxy for the gateway                                                                    | Webpack: slower and needs much more configuration for the same result. Create React App is deprecated                                                                              |
| Routing                    | React Router 7 (library mode)                         | Route-level `lazy` loading, layout routes for guards, nested routes, search params for shareable filters                                                                                          | TanStack Router: stronger typing of paths, but a steeper learning curve for no gain here                                                                                           |
| Server state               | TanStack Query                                        | Caching, loading and error states, invalidation after mutations, polling and cursor pagination out of the box. Nearly all state in this app is server data                                        | RTK Query: heavier and tied to Redux. Hand-written `useEffect` fetching: repeats caching, race and error code in every feature                                                     |
| Global client state        | Zustand                                               | Only three small stores are shared (session, theme, toasts); no providers, no boilerplate, readable outside React (the fetch client reads the session)                                            | Redux Toolkit: justified for large shared state, which this app does not have. React context: re-renders consumers and needs more wiring                                           |
| Local state and forms      | React state, React Hook Form with Zod                 | Uncontrolled inputs keep forms fast; the Zod schema is the single source of rules and gives typed values and messages                                                                             | Formik: heavier and less maintained. Native constraint validation alone: harder to give consistent messages and to test                                                            |
| UI components              | Own design kit on CSS Modules and design tokens       | Full control of light and dark themes and of accessibility, no unused library code, a small bundle, and a custom design kit is one of the assessed directions                                     | MUI, Mantine, Ant Design: faster to start but heavier, harder to bring to one visual identity and to WCAG contrast in both themes                                                  |
| Styling                    | CSS Modules reading CSS custom properties             | Scoped class names, no runtime cost, the tokens switch the whole interface by changing one attribute on `html`                                                                                    | Tailwind: fine, but tokens in plain CSS keep the theme system explicit. CSS-in-JS: runtime cost                                                                                    |
| API types                  | `openapi-typescript` from the backend's OpenAPI files | The backend contract is the source of truth; no hand-copied types that drift                                                                                                                      | Hand-written types: drift. Full generated clients (orval): an extra generated layer to maintain                                                                                    |
| API transport              | One small `fetch` wrapper                             | Under 100 lines, one place for the token, error mapping and relative paths; easy to test with MSW                                                                                                 | Axios: an extra dependency for features the wrapper does not need                                                                                                                  |
| Sign-in                    | `fetch` to Cognito `InitiateAuth`                     | The only calls needed are sign-in and refresh, about 40 lines                                                                                                                                     | AWS SDK or Amplify: far larger than the two calls it would replace                                                                                                                 |
| Session storage            | `sessionStorage`                                      | Survives a page reload, ends with the tab, never sent to a server by the browser. It is readable by script, so the application avoids `dangerouslySetInnerHTML` and keeps third-party scripts out | Memory only: safest against script injection but a reload signs the user out. `localStorage`: persists after the tab is closed. Cookies: the gateway expects the token in a header |
| Fonts                      | Source Serif 4 and Inter, bundled                     | Open licence (OFL), no third-party request, variable fonts keep the file count low                                                                                                                | Google Fonts CDN: an extra origin and a privacy and speed cost                                                                                                                     |
| Unit and integration tests | Vitest, Testing Library, MSW                          | Same config as Vite, tests exercise the screen as a user does, MSW fakes the network without mocking the code under test                                                                          | Jest: needs more configuration with Vite. Cypress component tests: heavier                                                                                                         |
| End-to-end tests           | Playwright with axe-core                              | Drives a real browser against the real stack, runs accessibility checks in the same flow                                                                                                          | Cypress: viable, Playwright's multi-browser and tracing were preferred                                                                                                             |
| Quality                    | ESLint (type-aware) and Prettier                      | Catches `any`, unhandled promises and hook mistakes; one format for everyone                                                                                                                      | None                                                                                                                                                                               |

## Why no Redux

The assessment accepts "local state plus global state, or an explanation of why it is not needed". Global state
here is three small, unrelated values: who is signed in, which theme, which toasts. Everything else the screens
show is server data that TanStack Query fetches, caches and invalidates. Adding Redux would add actions,
reducers and selectors for state that is not complex, so it was left out; the two layers (server cache and three
tiny stores) are enough and are easier to read.

## Trade-offs accepted

- **Own design kit instead of a library** costs more writing and testing of accessibility details (focus,
  dialogs, form errors) but gives a consistent look in both themes and a small bundle.
- **`sessionStorage` for tokens** is readable by script. The mitigations are in the code (no raw HTML
  rendering, links from the backend are limited to `http` and `https`) and a strict Content Security Policy is
  listed in [to be done](to-be-done.md).
- **Generated types** depend on the backend repository being next to this one when `npm run gen:api` runs; the
  generated files are committed so a build does not need it.
